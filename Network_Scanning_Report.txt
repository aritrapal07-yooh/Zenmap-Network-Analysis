1. PROJECT OVERVIEW

This practical demonstrates the use of Nmap through the Zenmap graphical
interface to examine a single target host. The scan output was reviewed
for host availability, open TCP ports, operating-system fingerprinting
information, and traceroute details.

2. OBJECTIVES

-   Understand basic network scanning and host discovery.
-   Observe open TCP ports on the selected target.
-   Review Nmap’s service and operating-system detection output.
-   Interpret traceroute and network-distance information.
-   Record findings and limitations accurately.

3. TOOLS AND ENVIRONMENT

-   Nmap 7.99
-   Zenmap (graphical interface for Nmap)
-   Kali Linux environment

4. SCAN CONFIGURATION

The Zenmap screenshot shows the profile “Intense scan, all TCP ports”.
The displayed Nmap command was:

    nmap -p1-65535 -T4 -A -v [REDACTED_TARGET]

The target address and hostname have been redacted in this public
report. The screenshots show one target host. The scan covered TCP ports
1 through 65535 and enabled Nmap’s aggressive detection features. The
scan was completed in the captured terminal output.

IMPORTANT SCOPE NOTE: The address visible in the original screenshot
begins with 192.178. That is not part of the private 192.168.0.0/16
range. Before publishing raw scan files or screenshots, confirm that the

These service names are the conventional associations for the port
numbers. The supplied screenshots do not show confirmed service-version

6. OPERATING SYSTEM DETECTION

Nmap displayed several possible operating-system guesses, including
Windows and Linux families, as well as an embedded-device possibility.
However, the output explicitly stated:

    No exact OS matches for host (test conditions non-ideal).

Therefore, the operating system could not be identified reliably from
this scan. The guesses should not be treated as a confirmed operating
system.

7. ANALYSIS AND LIMITATIONS

-   Four TCP ports were reported open in the Zenmap output.
-   Open ports indicate that a service may be accepting connections;
    they do not, by themselves, prove that a vulnerability exists.
-   The screenshots do not provide enough evidence to identify software
    versions or validate vulnerabilities.
-   OS fingerprinting was inconclusive.
-   No vulnerability exploitation or penetration testing was performed.
-   Findings describe only the target and scan conditions shown in the
    evidence.

8. SECURITY RECOMMENDATIONS

For the authorized system owner: - Confirm that each exposed service is
required for business purposes. - Restrict DNS, web, and mail services
to intended networks and users. - Keep the software providing these
services patched and supported. - Use firewall rules to limit
unnecessary inbound access. - Review service configuration and
authentication controls. - Investigate unexpected exposure through the
system owner or administrator.

10. CONCLUSION

This practical provided experience using Nmap and Zenmap to observe host
availability, open TCP ports, traceroute information, and OS-detection
output. The scan reported ports 53, 80, 110, and 443 as open.
Operating-system identification remained inconclusive, and the available
evidence does not establish that any vulnerability is present. The
results have been documented with the target identifiers redacted.
